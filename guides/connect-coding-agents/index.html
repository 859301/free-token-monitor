先看协议：工具要什么，密钥给什么

接不上的最常见原因是协议不匹配。不同工具要求的协议不同（以各工具官方文档为准，工具版本更新可能改变支持的协议）：

工具要求的协议
Claude CodeAnthropic 协议
Codex CLIResponses API
Cline多协议，含 OpenAI 兼容格式
OpenCode多协议，含 OpenAI 兼容格式

一条只提供 OpenAI Chat Completions 格式的免费密钥，无法直接插进要求 Anthropic 协议或 Responses API 的工具。接之前先确认两点：工具支持的协议，以及你的密钥提供的是哪种协议。

通用接入步骤

  1. 在工具的官方文档里找到配置入口与配置项（Base URL、API Key、模型名的填写位置）；不要凭记忆拼配置项名称。
  2. 按厂商官方文档填写 Base URL 与模型名；本站数据未注明 Base URL 与模型 ID 的额度，以厂商官方页面为准。
  3. 先用一个小请求验证：能返回结果再接正式任务。
  4. 检查模型是否支持工具调用（function calling）：编程工具依赖工具调用执行命令、读写文件；有的免费模型不支持或支持得不可靠，接上后会报错或行为异常。

两个常见坑

  • Base URL 路径重复：有的工具要求填到 /v1，工具自己拼 /chat/completions；两边都加会 404。见 常见问题 Q6。
  • 客户端内额度不能外接：Qoder、WorkBuddy、CodeBuddy、TRAE、Kiro 的注意事项都写明「仅限自家客户端内使用」，积分不能导出成 API Key 接入其他工具。
