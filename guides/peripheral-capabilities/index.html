定时任务、队列与搜索：周边能力怎么安排

本页更新于 2026-11-13

周边能力指主功能之外的支撑能力：定时任务、消息队列、搜索、缓存。安排原则是主栈自带优先：部署平台、数据库或监控服务自带的能力先用起来，不够用再另找服务。一个能力单独开一个服务，会增加配置与运维面。

定时任务

定时任务是按固定时间自动跑的活：每天凌晨清理过期数据、每小时拉一次外部数据、每周发一次汇总。覆盖方式有三种：部署平台自带的定时触发（见部署与托管列表里各条的详情页）、VPS 上自建（见免费 VPS 列表）、监控服务的 cron monitor（Sentry 免费档含 1 个 cron monitor）。定时任务跑失败时要有提醒，不然失败几天都不知道。独立定时任务服务与队列服务的排程能力见定时任务与队列列表。

消息队列

消息队列是把耗时的活排队慢慢做：发邮件、生成图片、处理上传文件，先接单、后处理，用户不用等。覆盖方式：部署平台自带的队列（Cloudflare Workers 配套免费量含 Queues 10,000 ops/天）、Redis（Upstash Redis 免费档可作队列与缓存）。量小的时候，数据库里一张任务表加定时任务也能顶一阵子。独立队列与工作流服务见定时任务与队列列表。

搜索

搜索分两种：站内全文搜索（用户搜自己的内容）与向量搜索（按语义找相似内容）。向量与 Embedding 额度的对照见免费向量与 Embedding 额度对比；搜索 API 额度的对照见免费搜索与抓取 API 对比。内容量小的时候，数据库的模糊查询够用，不用单独上搜索服务。

缓存

缓存是把算过的结果存起来，下次直接取，省数据库查询与 API 调用。覆盖方式：Redis（Upstash Redis 免费档：250 MB 数据量、每月 10 GB 带宽、每月 500K 命令）、CDN 缓存静态内容（见域名列表里的 CDN 条目）。缓存要定过期时间，不然旧数据一直被当成新的。

安排原则

  • 主栈自带优先：部署平台、数据库、监控服务自带的能力先用，用熟了再看缺什么。
  • 用量没到上限之前，不用急着升级：各条的免费量与超额规则见各自详情页。
  • 一个能力一个服务会增加运维面：每多一个服务，就多一套账号、密钥与账单。
  • 失败要有提醒：定时任务与队列跑失败时，监控与告警要能发现。见监控分析列表。
