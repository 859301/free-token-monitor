图标合规落地：声明保留怎么做

发布于 2026-11-15 · 更新于 2026-11-15 · 核实于 2026-11-14

图标授权的合规动作不在界面上，在分发物里：声明要随副本保留，注释不要删，品牌图标只用于指代本身。做法按各许可文本执行。

Font Awesome：嵌入注释勿删

下载的 Free 文件已含足够署名的嵌入注释，正常使用无需额外动作；许可页请求不要主动删除注释、尤其是代码中的注释。区分文件类型：图标 CC BY 4.0、字体 OFL 1.1、代码 MIT。

Lucide：两部分声明都要保留

ISC 部分与 Feather 派生图标的 MIT 部分，声明保留义务覆盖两部分：版权声明与许可声明出现在全部副本中（MIT 部分为全部副本或实质部分中）。

Heroicons：以 LICENSE 文件全文为准

已读副本中 MIT 条件句缺失半句，声明保留义务以仓库 LICENSE 文件全文为准，不凭通用文本补写。

构建工具与注释

构建与打包工具可能去掉文件中的注释，须按各许可文本检查声明是否保留（此点提醒以各许可文本为准）。分发物中声明缺失的，按所用许可文本补齐。

品牌图标只用于指代本身

Font Awesome 品牌图标只用于指代其所代表的公司、产品或服务，不得用于其他目的。Lucide 授权页与 Heroicons LICENSE 文件未提及品牌图标，以官方页面为准。

Iconify：按集合核对

Iconify 各集合许可不同：CC BY 4.0 集合涉及署名义务，MIT / Apache 2.0 集合涉及声明保留义务，具体以各集合许可文本为准；换集合时重新核对。

常见问题

图标声明要放在界面上吗？

Lucide 与 Heroicons 的义务是声明随副本保留（源码与分发物中），非界面署名；Font Awesome 靠嵌入注释满足署名，许可页未要求界面可见署名。

构建工具把注释去掉了怎么办？

须按各许可文本检查声明是否保留，分发物中声明缺失的，按所用许可文本补齐。
