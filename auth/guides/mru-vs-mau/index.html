MRU 与 MAU 有什么不同：Clerk 留存用户定义与 Auth0 外部活跃用户

核实于 2026-11-13 · 本页更新于 2026-11-13

MRU 与 MAU 是不同的计量口径。Clerk 的 MRU：用户在注册 24 小时后回访即计为 retained（“A user is counted as retained when they return 24+ hours after signing up.”）。Auth0 的 MAU：官网表述为 “External Active Users”（外部活跃用户），至多 25,000；活跃的判定细节在官网已读页面中未述。Supabase Auth 50,000 MAU 与 Firebase Auth 50K MAU 用的也是 MAU，判定细节以官方页面为准。口径不同，数字不能直接比大小。

MRU 的定义

Clerk 的 MRU（monthly retained user，每月留存用户）定义：用户在注册 24 小时后回访即计为 retained。官网原文：“A user is counted as retained when they return 24+ hours after signing up.”也就是说，计入 MRU 的是回访用户，不是注册当天的用户。Hobby 免费版每个应用 50,000 MRUs。

MRO 的定义

Clerk 的 MRO（monthly retained org，每月留存组织）定义：组织至少 2 名成员，且至少 1 名为当月 retained 用户。Hobby 免费版每个应用 100 MROs。超 100 MRO 须升级 B2B 附加项。

MAU 的表述

Auth0 的 MAU 表述为 “External Active Users”（外部活跃用户），免费档至多 25,000，定价页 FAQ 确认 25,000 阈值。活跃的判定细节在官网已读页面中未述，以官方页面为准。Supabase Auth 50,000 MAU 与 Firebase Auth 50K MAU 用的也是 MAU，判定细节以官方页面为准。

为什么不能直接比大小

MRU 计的是回访用户（注册 24 小时后回访），MAU 计的是活跃用户（判定细节以官方页面为准）。两个口径的定义不同，50,000 MRUs 与 25,000 MAU 两个数字不能直接比大小。同样，Clerk 的 100 MROs 与 Auth0 的 5 个组织口径也不同，不能直接比大小。

看额度数字时注意什么

看定义原文：Clerk 的 MRU 与 MRO 定义见上，Auth0 的 MAU 表述为 External Active Users。看计量范围：Clerk 的 50,000 MRUs 按应用计；Auth0 的 25,000 MAU 的计量范围在官网已读页面中未述，以官方页面为准。看超限规则：Clerk 写明强制升级与 1 个月宽限期，Auth0 超限行为以官方页面为准，见认证额度超了怎么办。
