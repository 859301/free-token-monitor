域名验证基础

核实于 2026-11-13 · 本页更新于 2026-11-13

域名验证是证明“这个域名归发件人所有、授权这家邮件服务代发”的步骤，通用做法是在域名的 DNS 里添加服务商提供的 SPF 与 DKIM 记录，再回到服务商后台确认验证通过。各家提供的记录值不同，以官方页面为准。

为什么要验证域名

邮件服务商需要确认发件域名归发件人所有，才允许用该域名发信。验证通过后，收件方可以依据 DNS 里的记录核对发件身份。验证是发件身份认证的基础步骤，不等于送达保证：是否进入收件箱还受收件方策略与发件行为影响，具体规则以各收件方与服务商的官方页面为准。

SPF：授权发件服务器

SPF（Sender Policy Framework）是一条 DNS TXT 记录，列出哪些服务器被授权用该域名发信。收件方收到邮件后查询该记录，核对实际发件服务器是否在授权列表里。SPF 记录的具体内容由邮件服务商提供，不同服务商的记录值不同，以官方页面为准。

DKIM：签名验证

DKIM（DomainKeys Identified Mail）用密钥签名邮件：发件方用私钥给邮件签名，公钥放在 DNS 记录里，收件方用公钥验证签名，确认邮件在传输中没有被改动、确实由该域名授权发出。DKIM 的选择器名称与公钥记录由邮件服务商提供，以官方页面为准。

通用验证步骤

  1. 在邮件服务商后台添加发件域名，服务商会给出需要添加的 DNS 记录（SPF、DKIM）。
  2. 到域名注册商或 DNS 服务商的 DNS 管理界面，按服务商给出的记录类型、主机记录与记录值添加记录；记录值以官方页面为准。
  3. 等待 DNS 记录生效后，回到邮件服务商后台触发验证，查看验证状态。
  4. 验证通过后，再用该域名发信；验证未通过时按服务商后台的提示核对记录。

域名注册与 DNS 服务本身见域名 / DNS / CDN / SSL 列表。

验证状态与排查

验证状态一般在邮件服务商后台查看。常见未通过原因按通用经验有三类：DNS 记录填错（主机记录或记录值与服务商给出的不一致）、DNS 记录尚未生效、同一个域名在多家服务商的记录互相冲突。排查时以服务商后台的提示与官方文档为准，记录值不要凭记忆填写。

Resend 免费计划含 3 个域名；Mailgun 免费计划含 1 个自定义发送域名。Brevo、SendGrid 试用、Postmark 的域名数量上限在官网已读页面中未述，以官方页面为准。多域名场景按各家上限核对。
